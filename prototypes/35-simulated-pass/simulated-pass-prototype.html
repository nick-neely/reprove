Exact fixture

One scenario, controlled faults

The same scenario runs under each supported Docker and Podman conformance job. It has no real Provider spend and no nondeterministic Model judgment.

Fixed Run specification

  • External Provenance, verify Autonomy, standard Strategy.
  • Codex stays pinned; the test registry injects a Codex-shaped double that never enters the production registry.
  • Base-ref resolved configuration is normalized, bounded, and secret-free.
  • Exposure: none plus rootless Isolation permits external Provenance without ADR 0004's scoped-credential opt-in.

Sandbox-owned inputs

  • A tiny Workspace contains src/cart-total.ts with one normal-path defect.
  • The test command is node --test and deterministically exposes the defect.
  • Protected narrative is exact encoded JSON, absent from argv, env, and instructions, and immutable to the Reviewer identity.
  • A local fake Provider sits behind the broker; only a placeholder enters the Sandbox.

Codex Adapter double output

  • One complete internal Adapter output with one verified high-severity Finding.
  • The claimed command, exit code, bounded excerpt, and location are fixed.
  • Observed tool activity independently records the same command and result.
  • No Patch is emitted under verify Autonomy.

Expected accepted Result

  • ClaimedEvidence survives the Worker-side Evidence cross-check and becomes Evidence.
  • The candidate Result waits until the exact Sandbox proves clean teardown.
  • Worker core can return a bounded complete or partial plain-JSON Result.
  • The caller parses it again with @reprove/protocol/v1.

Destination coverage

Join the contracts, do not duplicate their suites

The tracer consumes real proof records and exercises every gate. Dedicated suites keep the exhaustive canaries and golden fixtures owned by their packages.

Sandbox and credential

The tracer consumes a fresh host fingerprint and per-instance attestation, then proves clean teardown.

Docker and Podman conformance tests still own every namespace, egress, broker, resource, and residue canary.

Instruction and narrative

A stale instruction-boundary fingerprint Refuses before creation. Narrative setup asserts exact bytes, SHA-256, channel absence, protected ownership, and replacement denial.

Evidence and completeness

The same scenario covers successful Evidence, one bounded repair turn, repair exhaustion, and a partial Result with a retained Finding.

Compatibility

The tracer parses a valid additive-field RunSpec and asserts stripping at both seams. The protocol package keeps version mismatch, invalid invariants, and limit boundaries in its golden-fixture suite.

            Required terminal distinction
            
    Refusal before execution, Failure after it
    
            
    
              A missing hard boundary returns a structured Refusal only while the fixture Reviewer
              has not started. Evidence mismatch or teardown residue occurs after execution and must
              become Failure, because re-offering after execution could double-spend the Run.
            
    
          
    

          
    
            Phase 0 Failure transport
            
    Internal Worker outcome, no invented v1 message
    
            
    
              The tracer asserts an internal Worker-core Failure code. Phase 0 v1 has no terminal
              progress message, so a Failure produces no Result or Refusal payload here. The
              self-hosted transport that later distinguishes it from worker_lost stays
              with the progress and lifecycle protocol.
