The Worker validates RunSpec on entry and validates its own Result or Refusal before return. The control plane applies the same authoritative parser again because the Worker is untrusted.

Guided walkthroughs

The awkward cases, in order

A Run can cross and finish without scheduling protocol

Start with the fixed input, then return the smallest honest success. Nothing here requires enrollment, claim, lease, progress, HTTP, or a hosted Workflow seam.

Adapter output cannot masquerade as a wire Result

The Adapter reports claimed Evidence and observed tool calls separately. Posting that internal bundle directly fails. Only Worker core may cross-check it and construct the wire-visible Evidence carried by a Result.

Additive evolution is allowed, settled invariants are not

A valid fixture with a future optional field is accepted and stripped. Negative fixtures exist only for invariants already settled by ADR, so the suite does not declare every unimplemented Phase 1 behavior invalid.

A pre-execution refusal is data, not a degraded Run

The Worker names the failed requirement and the resolved facts. It does not claim that no Worker could ever serve the Run, and it does not silently weaken the requirement.
